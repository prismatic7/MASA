# MASA protocol audit — 2026-08-06

Status: completed local audit, project-agnosticism pass, and defect repair  
Scope: this repository's working tree only  
Protocol and reference implementation: `0.1.0` unreleased local working line

## Conclusion

MASA now carries no reference to any originating or consuming application anywhere in its normative artifacts, reference implementation, examples, adapters, or documentation. Canonical identifiers moved from a host-application domain to the protocol's own root, `https://masa.sonicfield.org/`, held in one generator constant and enforced by both generation and schema checking. The audit also repaired one broken security-relevant flow (public projection could not decorrelate identities), one critical packaging defect (installed bins were silent no-ops), several validation and bundle-safety defects, and a set of determinism and evidence-integrity gaps. The full local gate passes: build, 26 meta-valid schemas, 51 tests across 9 files, 8 valid and 9 invalid examples with pinned expected diagnostics, 1 bundle fixture, five conformant classes, publint, artifact inspection, and isolated packed-runtime smoke including symlinked-bin execution.

## Project-agnosticism pass

- **Canonical identifiers.** Every schema `$id`, the `$schema` and `@context` constants, the vocabulary namespace, capability and implementation identifiers, and example URLs migrated from the former host-application domain to `https://masa.sonicfield.org/…`. The root lives in `scripts/canonical.ts`; `check-schemas` and `generate-artifacts` both refuse non-canonical identifiers, and the capability catalog's schema URIs are cross-checked against registered `$id`s.
- **Adapters.** The four application-named adapter documents became neutral archetypes with placeholder namespaces: `studio-application.md` (`studio:`), `generative-engine.md` (`engine:`), `sonification-system.md` (`sonify:`), and `public-web.md` (`web:`). The adapter README states that archetypes are illustrative and that concrete applications document adapters in their own repositories.
- **Ontology provenance.** Term-registry references now cite the published works themselves (Schaeffer, Chion, Roads, Oliveros, Voegelin, Hui, Rivera Cusicanqui, Robinson) or MASA's own specification sections, instead of unreleased project documents. Opaque corpus `sourceIds` remain as provenance anchors.
- **Prose.** README, AGENTS, spec, and docs no longer name any application; cross-repository links were replaced with in-repository references. The 2026-07-29 audit record was neutralized in the same way while keeping its findings intact.
- **Vocabulary alignment.** `masa:Actor` and `masa:Context` joined the term registry, and the JSON-LD context now maps all Core entity types (including `Measurement`, `Region`, `Observation`, `Mapping`, `AgentRun`, `Capability`) and all sixteen entity collections.

## Defects repaired

### Security and correctness

- **Public projection could not decorrelate.** `createPublicProjection` copied publish receipts verbatim, so any record whose `publicRecordId` differed from its private id produced a candidate that failed its own audit (`recordId`, policy targets, and evaluation targets still named the private identity). The projection now rewrites every reference to the private record identity into the declared public identity; the private identifier no longer appears anywhere in the emitted artifact. Covered by new unit tests and a validator round trip.
- **Installed bins were silent no-ops.** The ESM entry guard compared `pathToFileURL(process.argv[1])` with `import.meta.url`; Node realpaths the main module but not `argv[1]`, so the pnpm/npm `.bin` symlinks executed nothing and exited 0. Both entry points canonicalize `argv[1]` first, and the packed-runtime smoke test now executes the CLI through a symlink.
- **Prototype-chain ontology lookups.** Registry lookups accepted inherited member names (`constructor`, `toString`) as registered relation predicates, fabricating lineage and false cycles on unvalidated input. All lookups are now `Object.hasOwn`-guarded (lineage tracing, derivation graph, descendant receipts, profile table).
- **Projection under-reported omissions.** Record-level extension omissions were appended to the returned report after the embedded `publication.omissions` snapshot was taken; the published record now carries them too.
- **MCP output leaked resolved paths.** Operating-system error messages (which embed absolute resolved paths) were copied into tool results; only MASA-coded messages are forwarded now, with errno preserved as the diagnostic code. Verified by test.
- **ZIP promote race.** `rename(2)` replaces an empty destination directory, so unpack promotion could clobber a concurrently created directory despite the refuse-overwrite promise; promotion now claims the destination with `mkdir` first.
- **Folded-name ancestor collisions.** A ZIP containing file `Dir` plus `dir/child` passed inspection but always failed extraction; the file-as-ancestor check now folds names exactly like the sibling check.
- **Unmanifested empty directories.** Stray ZIP directory entries were accepted at inspection and silently dropped on round trips; a directory entry must now be an ancestor of a manifested file (`MASA_BUNDLE_UNMANIFESTED_ENTRY`).
- **CLI conformance crash.** A record without `masaVersion`/`profiles` crashed the `conformance` command during output serialization (exit 3, raw TypeError) instead of reporting a structured failure; and `verify`/`pack`/`unpack` swallowed `BundleValidationError`, dropping all diagnostics and reporting an IO failure. Both fixed, both tested.

### Validation semantics

- Strict JSON now bounds nesting depth at 512 (`MASA_JSON_DEPTH`) and rejects numeric overflow to infinity, so hostile input degrades to diagnostics instead of stack exhaustion anywhere downstream.
- Derivation-cycle detection is iterative; a 30,000-edge chain no longer overflows the call stack (regression test included).
- Leap-second timestamps that the `date-time` format accepts no longer produce false `MASA_TEMPORAL_ORDER` errors; unparseable-but-schema-valid instants skip interval ordering uniformly.
- A completed `expire` operation now requires an authorizing policy evaluation (it was the one consequential effect class exempted).
- Publication prohibitions now also apply when a rule names a contained entity rather than the record identity.
- The public audit gained: string-valued coordinates, additional filesystem roots (`/mnt`, `/srv`, `/media`, `/data`, `/run`), CGNAT/0.0.0.0/IPv4-mapped-IPv6 private ranges, and more credential key/value shapes (`accessToken`, `client_secret`, `sk_live_…`). `isPrivateHostname` is now a single shared implementation exported from core.
- Byte-identical diagnostics emitted by overlapping audit phases are deduplicated; diagnostic ordering is pinned to the `en` locale everywhere (it was host-locale-dependent, so orderings could differ across machines).
- `summarizeRecord` counts embedded events from the history array, no longer undercounting duplicate-id receipts.
- Lineage traces keep relations whose endpoints are both inside the trace at the depth frontier (they were silently dropped with `truncated: false`).

### Evidence and harness integrity

- The fixture digest is codepoint-sorted with POSIX labels, filtered to fixture extensions, and now also covers `schemas/`, `ontology/`, and `contexts/` — a normative change can no longer leave recorded evidence looking current. Recorded evidence digest: `88db8987baf0d87897eb3a874bbf769cfdef7691e86161d47cf0c3eac908d310`.
- Invalid examples must fail with their expected diagnostic codes (table-driven, set-equal to the fixture directory); a validator crash no longer counts as a correct rejection in either the script or the conformance runner.
- Fixture counts are exact (26 schemas, 8 valid, 9 invalid); a conformance class whose declared tests go missing now fails instead of reporting shrunken coverage as conformant.
- The generation fixture's policy rule actually permits `generate` (it previously permitted only read/validate/transform while its receipt claimed an explicit permission).
- The packed-artifact inspector's personal-path scan matches any user home path rather than one hardcoded username, and tolerates future package READMEs.
- Example generation is idempotent (write-if-changed), and the mapping/generation fixtures embed no application vocabulary.

## Compatibility decision

The canonical-identifier migration invalidates any record written against the pre-migration `$schema` constant. `0.1.0` remains unreleased and has never been published, packaged, or deployed; no conforming external record exists. The change is therefore recorded as a working-draft repair in `CHANGELOG.md` under the same rationale as the 2026-07-29 absence-state repair. After release, an equivalent change would require the versioning and migration procedure.

## Accepted residual risks and boundaries

1. The MCP realpath-then-open sequence can be raced by a same-machine process swapping path components; recorded in `threat-model.md` as accepted for a local, read-only, same-user tool.
2. Bundle packing re-verifies file identity before adding entries but the archive library reopens files; a concurrent local writer is caught by the packed artifact's self-verification rather than prevented.
3. Secret, coordinate, path, and private-endpoint scanning remain defense in depth; policy stays the authority.
4. Cross-language SDKs, signatures, remote registries, MCP write tools, and audio processing remain out of scope for 0.1.0, as documented.
5. Projection and audit pointer segments are not JSON-Pointer-escaped for exotic keys; safe for all schema-constrained names.
